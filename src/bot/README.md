# `@preference/bot` — бот-соперник

Игровой ИИ для преферанса: оценка руки, торговля, снос, вист и розыгрыш.
Позволяет играть **одному против двух ботов**.

**Источник истины по правилам:** [`docs/rules.md`](../../docs/rules.md)
(`rules-v1`, конвенция «Сочи», 3 игрока). При расхождении кода и документа
прав документ. API движка — [`src/engine/README.md`](../engine/README.md).

## Бот — это функция `(DealState) -> Command`

```ts
import { createBot } from './src/bot/index.js';
import { createDeal, dispatch, expectOk } from './src/engine/index.js';

const bot = createBot({ level: 'hard', seat: 1, seed: 'game-42' });

let state = createDeal({ seed: 'game-42', dealer: 0 });
while (state.phase !== 'RESULT') {
  const command = state.toAct === 1 ? bot.decide(state) : humanMove(state);
  state = expectOk(dispatch(state, command)).state;   // отказ = баг бота
}
```

Бот не хранит состояние партии: единственное, что он помнит между вызовами, —
свой ГПСЧ. Всё остальное выводится из `DealState`, поэтому решение
воспроизводимо и его легко разбирать в отладке.

## Главный инвариант: нелегальный ход невозможен структурно

Бот **никогда не конструирует действие сам** — он выбирает из множеств,
которые уже посчитал движок:

| Фаза | Источник вариантов |
|---|---|
| `BIDDING` | `state.bidding.legalBids` (§3.3, §3.7) |
| `FINAL_CONTRACT` | `state.legalContracts` (§4.3) |
| `PLAY` | `state.legalMoves` (§6.2) |

То же и внутри Monte-Carlo: симуляции гоняют ядро `src/core`
(`legalMoves`/`applyMove`), а не собственную копию правил. Поэтому
приёмка «бот никогда не делает нелегальный ход» выполняется по построению,
а фузз на 1000 раздачах её подтверждает.

## Уровни сложности

| Уровень | Торговля и вист | Розыгрыш | Время на ход |
|---|---|---|---|
| `easy` | случайно, но легально | случайная легальная карта | < 1 мс |
| `normal` | оценка руки | эвристики §6–§8 | < 1 мс |
| `hard` | оценка руки | Monte-Carlo, 60 сэмплов на ход | ≈ 34 мс |

```ts
createBot({ level: 'hard', seat: 0, seed: 'x', simulations: 120 });  // бюджет настраивается
```

## Как бот принимает решения

### Оценка руки (`evaluate.ts`)

Взятки считаются по мастям: непрерывная последовательность honor-ов от туза
(`A`, `AK`, `AKQ`) — **верные** взятки; honor с «дыркой» сверху — **полуверная**,
и только при достаточном прикрытии (королю нужна одна карта под ним, даме — две).
К честным взяткам добавляются бонусы за козырную длину (каждая карта сверх трёх)
и за короткие боковые масти (ренонс — взятка, синглет — половина), причём бонус
за короткость ограничен козырной длиной: подрезать нечем, если козырей нет.

`miserRisk` оценивает пригодность руки для мизера (§7): карта опасна, когда
своих младших карт под неё меньше, чем чужих недостающих рангов.

### Торговля (`bidding.ts`)

Заявляется самый дорогой контракт, чей уровень рука реально обещает; мизер —
только при риске ≤ 1 (заявка кабальная, §3.7). Если ни одна допустимая заявка
не покрывается оценкой — пас, и три паса дают распасы естественным образом.
Окончательный заказ, наоборот, берётся **минимальный** из подходящих: каждый
лишний уровень — это лишние взятки под ремиз (§9.5).

### Снос (`discard.ts`)

Оцениваются **пары карт**, а не карты по отдельности: снос двух карт одной
короткой масти даёт ренонс, а по карте из разных мастей — ничего. Козырь
неприкосновенен, стопперы сохраняются. На мизере логика обратная: сносятся
самые опасные карты (§7 п.3).

### Вист (`whist.ts`)

Вистуем, когда ожидаемые взятки покрывают обязательство обороны (§5.3):
норма зависит от контракта и от того, вистует ли партнёр. Недобор наказывается
ремизом на висте (§9.6), поэтому решение экономическое, а не «всегда вистовать».
Единственный вистующий просит игру **всветлую** — она даёт ему обе руки обороны.

### Розыгрыш (`play.ts`, `search.ts`)

Три цели, каждая со своей эвристикой:

* `win` — брать взятки: заходить со стопперов, брать **минимальной достаточной**
  картой, безнадёжную взятку отдавать самой слабой;
* `avoid` — распасы (§8.1): заходить мелочью, сбрасывать самую старшую из
  безопасных карт, вынужденную взятку брать минимальной;
* `catch` — против мизера (§7 п.6): заходить мелочью, а когда мизерист уже
  лидирует во взятке — **не перебивать** его.

Уровень `hard` поверх этого делает Monte-Carlo поиск: неизвестные карты
раздаются по скрытым рукам (`determinize`) с учётом выведенных ренонсов, каждая
карта-кандидат проверяется на **одинаковых** сэмплах, побеждает лучшая средняя.
Общие сэмплы дают и снижение дисперсии, и детерминизм при фиксированном seed.

## Четыре ловушки, на которых бот ломается

1. **Ходит не тот, чьи карты.** При висте всветлую вистующий играет и за
   пасовавшего: команду шлёт `state.toAct`, а карты берутся из руки
   `state.play.toPlay` (маппинг — `state.controlledBy`).
2. **Ответ партнёра по висту лежит в `state.whist.decisions`,** а `state.whisted`
   движок заполняет только после закрытия опроса. Бот, читающий `whisted`
   во время `WHIST_DECLARATION`, считает вистующего партнёра пасовавшим и
   получает `ILLEGAL_WHIST` на просьбе играть всветлую.
3. **Прикуп виден, но не локализован.** После взятия его карты лежат либо в руке
   игрока, либо в его **секретном** сносе (§4.1/§4.2). Для обороны это известные
   по номиналу, но неизвестные по местоположению карты — они обязаны остаться
   в пуле сэмплирования. Исключение — распасы: там прикуп в руку не берут (§8.2).
4. **Мизер не проходит через `WHIST_DECLARATION`** — состояние прыгает из
   `FINAL_CONTRACT` сразу в `PLAY` (§7.4), карты обороны открыты. Это полная
   информация, MC-сэмплирование здесь не нужно.

## Проверка

```bash
npm run gate                          # tsc --noEmit + быстрые тесты (351 тест, ~6 с)
npm run test:acceptance               # приёмка: фузз 1000, матч уровней, бенчмарк (~4 мин)
python scripts/mutation_check_bot.py  # мутации решений бота
```

### Приёмочные критерии задачи

| Критерий | Результат |
|---|---|
| Бот никогда не делает нелегальный ход (1000 раздач) | 1000/1000 доходят до `RESULT`, ни одного отказа движка |
| `hard` выигрывает у `easy` минимум в 70% из 200 раздач | **50/50 матчей (100%)**, 200 раздач |
| Средний ход быстрее 500 мс | **≈ 34 мс** на решение |

Дополнительно: `normal` обыгрывает `easy` 15/15 — уровни упорядочены по силе.

Фузз смешивает уровни за столом и задевает все три ветки исхода: на 1000
раздачах — 654 контракта, 26 мизеров, 320 распасов. Однобокое распределение
означало бы фиктивное покрытие: например, при оценке руки без поправки на
прикуп (§4.1) распасами кончались 77% раздач, и ветка контракта почти
не проверялась.

Мутационная проверка: **25/25** намеренных поломок правил пойманы тестами.

## Матчи ботов (`match.ts`)

`playDeal` проигрывает одну раздачу тремя ботами, `playMatch` — серию раздач
с ротацией сдающего (§2.2) и счётчиком распасов (§8.4), сводя результат
настоящим `scoreDeal` из `src/scoring`. Отказ движка превращается в исключение
с текстом команды: это баг бота, а не игрока.

## Что модуль намеренно НЕ делает

Правила (они в `src/core`/`src/engine`), подсчёт очков (`src/scoring`), UI и
ведение партии. Бот только выбирает команду в предложенном состоянии.
