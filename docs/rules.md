# Правила преферанса — нормативная спецификация проекта

**Статус:** единственный источник истины (SSOT) для всей реализации.
**Конвенция по умолчанию:** «Сочи» («сочинка»), 3 игрока.
**Версия правил:** `rules-v1`.

Источники:

1. Википедия, статья «Преферанс» — <https://ru.wikipedia.org/wiki/Преферанс> (базовые правила: колода, раздача, торговля, розыгрыш, счёт, распасы, перечень выбираемых соглашений).
2. Описание конвенции «Сочи» — <https://www.gambler.ru/Preferans-sochi> (порядок распасов, «помощь», прикуп со взятками).
3. Таблица записи «сочинки» и перечень договорных правил — <http://pref-game1.narod.ru/rules_sochi.htm> (стоимость игр, консоляция, ответственный/жлобский вист, прогрессия распасов).

## Как читать этот документ

* Каждое правило либо **нормативное** (обязательно к реализации ровно так, как написано), либо помечено как **[КОНФИГ: `имя_параметра`]** — тогда указано значение по умолчанию и допустимые альтернативы.
* **В документе нет формулировок «возможно», «обычно», «по договорённости» без выбранного дефолта.** Любая вариативность вынесена в §10 и в JSON-конфиг (приложение А.2).
* Идентификаторы (`CardId`, `ContractId`, коды параметров) — нормативные: их обязаны использовать и модуль ядра, и модуль расчёта, и UI.
* Тестовые сценарии приложения Б имеют стабильные идентификаторы `TS-NN`. Юнит-тесты обязаны ссылаться на них.

## 1. Колода, карты, старшинство

### 1.1 Состав колоды

Малая колода — **32 карты**: 4 масти × 8 достоинств (от семёрки до туза). Джокеров нет.

### 1.2 Достоинства (ранги)

От младшего к старшему:

| Ранг | 7 | 8 | 9 | 10 | Валет | Дама | Король | Туз |
|---|---|---|---|---|---|---|---|---|
| Код (`Rank`) | `7` | `8` | `9` | `T` | `J` | `Q` | `K` | `A` |
| Сила (`rankOrder`) | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |

Старшинство карт **едино для всех типов игр** (игра на взятки, мизер, распасы). На мизере и распасах карты не меняют старшинства — меняется только цель игры.

### 1.3 Масти

| Масть | Пики | Трефы | Бубны | Черви |
|---|---|---|---|---|
| Символ | ♠ | ♣ | ♦ | ♥ |
| Код (`Suit`) | `S` | `C` | `D` | `H` |
| Сила в торговле (`suitOrder`) | 0 | 1 | 2 | 3 |

Масти **равноценны при взятии взяток** (старшинство мастей влияет только на торговлю и на то, какая масть назначена козырем). «Без козыря» — псевдо-масть в торговле с кодом `NT` и `suitOrder = 4`.

Старшинство для торговли по возрастанию:

```
пики (S) < трефы (C) < бубны (D) < черви (H) < без козыря (NT)
```

### 1.4 Идентификатор карты

`CardId = <Rank><Suit>`, например `AS` (туз пик), `TH` (десятка червей), `7C` (семёрка треф).
Каноническая сортировка колоды: по `suitOrder`, затем по `rankOrder` (`7S,8S,…,AS,7C,…,AC,7D,…,AD,7H,…,AH`) — **нормативна** для детерминированного seed-перемешивания.

## 2. Состав, раздача, роли

### 2.1 Состав

**Ровно 3 игрока.** Игра вчетвером (сдающий «сидит на прикупе»), гусарик (вдвоём) и составы 5+ — **вне области реализации** этой версии. Все правила ниже сформулированы для трёх игроков.

Игроки сидят по кругу и занумерованы `0,1,2` **по часовой стрелке**; порядок мест фиксирован на всю партию.

### 2.2 Сдающий и руки

* Сдающий в первой раздаче определяется жребием (в реализации — параметром/сидом).
* В каждой следующей раздаче сдающий смещается **на одного по часовой стрелке**: `dealer' = (dealer + 1) mod 3`. **[КОНФИГ: `dealerRotation`]** — значение по умолчанию `sliding` («скользящий переход»); альтернатива `repeat3` (одна и та же сдача трижды) не поддерживается движком v1.
* Переход сдачи происходит **после любой раздачи**, включая распасы и несыгранный мизер.
* Роли рук в раздаче (нормативно):
  * **Первая рука** = `(dealer + 1) mod 3` (слева от сдающего);
  * **Вторая рука** = `(dealer + 2) mod 3`;
  * **Третья рука** = `dealer` (при трёх игроках сдающий играет).
* Старшинство рук в торговле: первая > вторая > третья (используется правилом «здесь», §3.6).

### 2.3 Порядок сдачи

Сдача **детерминирована** (это важно для воспроизводимости тестов). Из перемешанной колоды карты разбираются строго так:

1. Круг 1: по 2 карты — первой руке, второй, третьей (6 карт).
2. Круг 2: по 2 карты — первой, второй, третьей (6 карт; всего 12).
3. **Прикуп: 2 карты** (карты №13 и №14 в порядке разбора).
4. Круги 3, 4, 5: по 2 карты — первой, второй, третьей (18 карт; всего 32).

Итог: по **10 карт** каждому игроку + **2 карты в прикуп**. Прикуп откладывается после второго круга — это удовлетворяет требованию Кодекса «никогда первой или последней парой карт».

### 2.4 Кто ходит первым

| Тип раздачи | Первый ход первой взятки |
|---|---|
| Игра на взятки | **Разыгрывающий (игрок)** |
| Мизер | **Мизерист (игрок)** |
| Распасы | **Первая рука** (после вскрытия карты прикупа, §8.2) |

В каждой последующей взятке первым ходит взявший предыдущую взятку. Исключение — третья взятка распасов (§8.2).

## 3. Торговля

### 3.1 Порядок заявок

Заявки объявляются строго по кругу по часовой стрелке, начиная с **первой руки**. Заявка игрока — либо `PASS`, либо значащая заявка.

### 3.2 Шкала значащих заявок

Значащая заявка — контракт на взятки (`6♠ … 10БК`) или `МИЗЕР`. Полная шкала старшинства (26 позиций):

```
1..5    6♠  6♣  6♦  6♥  6БК
6..10   7♠  7♣  7♦  7♥  7БК
11..15  8♠  8♣  8♦  8♥  8БК
16      МИЗЕР
17..21  9♠  9♣  9♦  9♥  9БК
22..26  10♠ 10♣ 10♦ 10♥ 10БК
```

`bidOrder(level, suit) = (level - 6) * 5 + suitOrder + 1`, с поправкой: все контракты уровня 9 и 10 сдвигаются на +1 из-за вставки мизера (`bidOrder = 16` у мизера). Нормативная таблица `bidOrder` — приложение А.1.

Минимальная возможная заявка — **`6♠`** («раз», `bidOrder = 1`). Максимальная — `10БК` (`bidOrder = 26`).

### 3.3 Правило повышения

Каждая новая значащая заявка обязана быть **строго старше** всех ранее объявленных (`bidOrder` строго больше текущего максимума).

**[КОНФИГ: `bidJumps`]** — по умолчанию `allowed`: разрешена заявка через ступень (например, после `6♠` сразу `9♥`). Альтернатива `stepByStep` (каждая заявка ровно на одну ступень выше) не является дефолтом.

### 3.4 Пас

`PASS` — отказ от игры на взятки и от мизера **в этой раздаче**; спасовавший **выбывает из торговли окончательно** и в дальнейшем заявок не делает.

### 3.5 Завершение торговли

* Как только **двое** игроков сказали `PASS`, а третий имеет значащую заявку — торговля окончена, этот третий становится **игроком (разыгрывающим)**.
* Если **все трое первым словом сказали `PASS`** — играются **распасы** (§8).
* Игрок, выигравший торговлю, **не может отказаться от игры** (кроме опционального «ухода без трёх», §4.5, который по умолчанию выключен).

### 3.6 Правило «здесь»

Когда в торговле остались только два активных участника, находящийся на **старшей руке** может не повышать заявку соперника, а перебить её **такой же**, сказав «здесь». Формально: заявка `HERE` допустима, если (а) активных участников ровно двое, (б) заявляющий старше по руке, чем автор текущей максимальной заявки. Эффект: текущий максимум остаётся, но право на контракт переходит к сказавшему «здесь»; соперник обязан либо повысить, либо спасовать.

### 3.7 Мизер в торговле

* `МИЗЕР` — **кабальная** заявка: может быть только **первой значащей заявкой этого игрока** в данной раздаче. Игрок, уже назвавший игру на взятки или спасовавший, объявить мизер не может.
* Мизер перебивается любой заявкой уровня 9 и выше (`bidOrder > 16`).
* **[КОНФИГ: `miserOvercall`]** — по умолчанию `simple`: «мизер — 9, дальше торговля не идёт»; заявок «мизер без прикупа» и «9 без прикупа» **нет**. Альтернатива `withoutPrikup` (М — 9 — мизер б/п — 9 б/п) в v1 не реализуется.
* Выигравший торговлю мизером **обязан** разыграть мизер.

### 3.8 Обязательный вист на `6♠` («Сталинград»)

**[КОНФИГ: `stalingrad`]** — по умолчанию `off`: вистование на `6♠` добровольное, как и на любой другой игре.

## 4. Прикуп, снос, окончательный заказ

### 4.1 Вскрытие прикупа

После окончания торговли сдающий переворачивает **обе карты прикупа лицом вверх** — их видят все участники — и передаёт игроку. При распасах прикуп используется иначе (§8.2).

### 4.2 Снос

Игрок берёт прикуп в руку (12 карт) и **сносит две любые карты**, никому их не показывая. Снесённые карты в розыгрыше не участвуют и взяток не берут. До момента окончательного заказа снос можно менять.

На мизере снос делается так же (мизер играется с прикупом, см. §3.7).

### 4.3 Окончательный заказ контракта

После сноса игрок объявляет окончательный контракт: количество взяток и козырь (или «без козыря»).

**Нормативное ограничение:** окончательный контракт обязан быть **не ниже** выигравшей заявки по шкале `bidOrder`.

Пример: торговля выиграна заявкой `7♦` (`bidOrder = 8`). Допустимо заказать `7♦`, `7♥`, `7БК`, любые 8, 9, 10. Недопустимо: `7♠`, `7♣`, любые шестерные.

Заказ выше выигравшей заявки **разрешён и не штрафуется**. Заказ мизера при выигранной торговле на взятки **запрещён** (мизер кабальный); заказ игры на взятки при выигранной торговле мизером **запрещён**.

### 4.4 Заявки вистующих

После окончательного заказа оба соперника по очереди **по часовой стрелке от игрока** объявляют `WHIST` или `PASS`. Возможные исходы — §5.

### 4.5 «Уход без трёх» (пас-контракт)

**[КОНФИГ: `withoutThree`]** — по умолчанию `off`. При включении: выигравший торговлю вместо окончательного заказа может отказаться от розыгрыша, записав себе в гору штраф за 3 недобранные взятки по стоимости игры, на которой закончился торг; висты при этом не пишутся.

### 4.6 «Прикуп со взятками» (быстрые взятки)

**[КОНФИГ: `paidPrikup`]** — по умолчанию `off`. При включении соперники пишут на игрока висты за пришедшие в прикупе «быстрые взятки»: туз **или** марьяж — 1 взятка текущего контракта, туз с королём одной масти — 2, два туза — 3; при трёх игроках сумма делится между соперниками поровну.

## 5. Вист: роли, обязательства, режимы розыгрыша

### 5.1 Роли

* **Игрок (разыгрывающий)** — выигравший торговлю.
* **Вистующий** — соперник, объявивший `WHIST`.
* **Пасующий** — соперник, объявивший `PASS` после заказа.

Обе стороны обороны — «стол»: игра ведётся **обороной против игрока**, а не каждым за себя.

### 5.2 Режимы розыгрыша обороны

| Ситуация | Режим | Нормативно |
|---|---|---|
| Вистуют оба | **втёмную** | Обязательно. Карты обороны закрыты, каждый ходит своими картами. |
| Вистует один | **втёмную или всветлую** | Выбирает вистующий. |
| Вистует один и выбрал «всветлую» | оба соперника кладут карты открыто, **вистующий делает ходы за себя и за пасующего** | Решение принимается **до первого хода игрока**. |
| Оба спасовали | розыгрыша нет | Игрок сразу получает очки за выполненный контракт (§9.3). |
| Мизер | **всегда всветлую** | Соперники открывают карты и играют совместно. |
| Распасы | **всегда втёмную** | Каждый за себя. |

**[КОНФИГ: `declarerFirstMove`]** — по умолчанию `light` («в светлую»): при висте всветлую и на мизере карты обороны открываются **до** первого хода игрока. Альтернатива `dark` (игрок ходит первым «втёмную», затем оборона открывается).

### 5.3 Обязательный вист (вистовые обязательства)

Вистующие принимают обязательство взять минимальное количество взяток. Обязательство задаётся **на всю оборону**:

| Контракт | Обязательство обороны, взяток | При двух вистующих — на каждого |
|---|---|---|
| 6 | 4 | 2 |
| 7 | 2 | 1 |
| 8 | 1 | 1 (см. ниже) |
| 9 | 1 | 1 (см. ниже) |
| 10 | 0 | 0 |
| Мизер | 0 | 0 |

* **Один вистующий** отвечает за **всю** норму обороны (4/2/1/1), и в зачёт ему идут взятки **всей обороны**, включая взятки пасовавшего (симметрично тому, что при жлобском висте он пишет висты за все взятки обороны, §9.4).
* **[КОНФИГ: `responsibility89`]** — по умолчанию `both`: на восьмерной и девятерной при двух вистующих обязательство «1 взятка» лежит на **каждом** из них; не взявший ни одной взятки пишет ремиз за 1 взятку. Альтернатива `last` (отвечает только последний вистующий).
* **[КОНФИГ: `tenPlayed`]** — по умолчанию `checked`: десятерная **проверяется**, вистовых обязательств нет. Механически движок разыгрывает раздачу обычным образом с нулевым обязательством; «проверка в открытую» — приём UI, не отдельная механика. Альтернатива `whisted` (десятерная вистуется с обязательством 1).

Недобор обязательных взяток называется **ремизом на висте** и наказывается записью в гору (§9.5).

### 5.4 «Полвиста» / «свой вист»

* **[КОНФИГ: `halfWhist`]** — по умолчанию `off`. При включении вистующий, оставшийся один после паса второго соперника, вправе отказаться от розыгрыша «за полвиста»: он пишет на игрока половину вистов, положенных за обязательные взятки, а игрок засчитывает контракт сыгранным.
* **[КОНФИГ: `ownWhist`]** — по умолчанию `off`. При включении на **шестерной и семерной** играх единственный вистующий может (с согласия игрока) взять «свои висты» без розыгрыша: он пишет на игрока висты за норму обязательных взяток, контракт считается сыгранным.
* **[КОНФИГ: `remiseWithoutVists`]** — по умолчанию `off` («отпустить игрока на ремизе без вистов» не допускается).

### 5.5 Игра «на распасах»

Если торговля не выявила ни одной значащей заявки (три паса), ролей «игрок/вистующий» нет: каждый играет за себя, цель — взять **как можно меньше** взяток (§8).

## 6. Правила хода и взятия

### 6.1 Взятка

Взятка — по одной карте от каждого участника (при трёх игроках — 3 карты). В раздаче ровно **10 взяток**. Ни номинал, ни порядок выкладывания карт не влияют ни на что, кроме определения победителя взятки: значение имеют только **принадлежность и количество** взяток.

### 6.2 Обязанность хода (`legalMoves`)

Первая выложенная карта задаёт **масть хода** (`ledSuit`). Нормативный алгоритм допустимых ходов:

```
legalMoves(state, player):
  if player делает первый ход во взятке:
      -> любая карта из руки            (ограничений нет, в т.ч. на выход с козыря)
  ledSuit := масть первой карты взятки
  if в руке есть карты ledSuit:
      -> только карты ledSuit           (обязанность ходить в масть)
  else if контракт козырный и в руке есть козыри:
      -> только козыри                  (обязанность козырять)
  else:
      -> любая карта из руки            (снос)
```

* **Обязанность ходить в масть — абсолютна.**
* **Обязанность козырять при отсутствии масти хода — абсолютна** (для козырных контрактов).
* На **бескозырных** контрактах, на **мизере** и на **распасах** козыря нет, поэтому второе условие никогда не срабатывает: при отсутствии масти хода играется любая карта (снос).
* **[КОНФИГ: `mustOvertake`]** — по умолчанию `off`: **обязанности бить старшей картой нет**. Игрок, дающий в масть или козыряющий, вправе положить любую карту разрешённого множества, в том числе заведомо младшую. Альтернатива `on` («обязан брать») — правило домашних компаний, движком v1 не поддерживается.
* Ошибочный ход не в масть при наличии масти хода — **фальшренонс**; в цифровой реализации такой ход просто недопустим (`legalMoves` его не содержит).

### 6.3 Победитель взятки (`trickWinner`)

```
trickWinner(trick, trumpSuit):
  if trumpSuit != null и во взятке есть козыри:
      -> положивший старший козырь
  else:
      -> положивший старшую карту масти хода (ledSuit)
```

Карты, сброшенные не в масть и не козырные, во взятии не участвуют никогда.

### 6.4 Конец раздачи

Раздача взяток окончена, когда у всех игроков не осталось карт (10 взяток). Досрочная фиксация результата («мои остальные взятки») — приём UI, эквивалентный доигрыванию; на подсчёт не влияет.

## 7. Мизер

1. **Контракт:** игрок обязуется **не взять ни одной взятки** из 10.
2. **Козыря нет.** Все масти равноценны; `trumpSuit = null`; правило хода — §6.2 без ветки козыря.
3. **Прикуп:** мизерист берёт прикуп и делает снос (§4.2). Мизер без прикупа в v1 отсутствует (`miserOvercall = simple`).
4. **Раскрытие карт:** соперники **обязательно** раскрывают свои карты и играют совместно (вист всегда «лёжа»). Порядок раскрытия относительно первого хода — `declarerFirstMove` (по умолчанию карты открываются **до** первого хода мизериста).
5. **Первый ход** делает мизерист.
6. **Вистовых обязательств у соперников нет**, их цель — заставить игрока взять как можно больше взяток.
7. **Запись:** мизер оценивается как десятерная — **10 очков**.
   * Сыграл (0 взяток) → **+10 в пулю**.
   * Каждая взятая игроком взятка → **10 в гору** («шпага»).
   * **Висты на мизере не пишутся** (ни за взятки соперников, ни консоляция) — **[КОНФИГ: `miserVists`]**, по умолчанию `none`. Альтернатива `asTen` (висты как на десятерной).
8. **Сдача после несыгранного мизера** переходит обычным порядком (§2.2).

## 8. Распасы

### 8.1 Условие и цель

Распасы играются тогда и только тогда, когда **все три игрока первым словом сказали «Пас»**. Цель каждого — взять **как можно меньше** взяток. Козыря нет, все масти равноценны, розыгрыш всегда **втёмную**, каждый играет за себя.

### 8.2 Прикуп на распасах

**[КОНФИГ: `prikupOnRaspasy`]** — по умолчанию `open` (прикуп открывается). Нормативная механика для трёх игроков:

1. **Первая взятка:** сначала вскрывается **верхняя карта прикупа** — она **задаёт масть хода**, но во взятии **не участвует** и взяток не берёт. Затем кладут карты игроки, начиная с **первой руки**, по часовой стрелке. Взятку берёт положивший **старшую карту масти хода** среди трёх игроков; если масть хода не положил никто (все трое снесли), взятку берёт **первая рука** (игрок, ходивший первым во взятке).
2. **Вторая взятка:** аналогично, вскрывается **вторая карта прикупа**; ходят игроки, начиная с **первой руки**.
3. **Третья взятка:** независимо от того, кто взял вторую взятку, первой ходит **первая рука**.
4. **Четвёртая и далее:** обычный порядок — ходит взявший предыдущую взятку.

Альтернатива `closed` (прикуп не открывается, масть первой взятки определяет первая рука) — не дефолт.

### 8.3 Подсчёт взяток и амнистия

Считается число взяток каждого игрока. Применяется **амнистия**: минимальное среди игроков количество взяток принимается за ноль.

```
штрафные_взятки(i) = взятки(i) - min(взятки)
```

### 8.4 Цена взятки и прогрессия

* **Базовая цена взятки на распасах: 1 очко в гору.** **[КОНФИГ: `raspasyTrickPrice`]**, по умолчанию `1`; альтернатива `2`.
* **[КОНФИГ: `raspasyProgression`]** — по умолчанию `limitedArithmetic`: множитель по счётчику подряд идущих распасов — **×1, ×2, ×3, далее ×3** (потолок). Альтернативы: `none` (×1 всегда), `limitedGeometric` (×1,×2,×4,×4…), `unlimitedArithmetic` (×1,×2,×3,×4…), `unlimitedGeometric` (×1,×2,×4,×8…).
* **Счётчик распасов** увеличивается на 1 с каждой раздачей подряд, закончившейся распасами, и **сбрасывается в 0 после любой сыгранной раздачи** (игра на взятки или мизер, независимо от результата).

```
цена_взятки = raspasyTrickPrice * множитель(счётчик распасов)
гора(i) += штрафные_взятки(i) * цена_взятки
```

### 8.5 Премия за ноль взяток

Игрок, не взявший на распасах **ни одной** взятки, получает премию: **+1 очко в пулю**, умноженное на текущий множитель прогрессии.

**[КОНФИГ: `raspasyZeroBonus`]** — по умолчанию `pool` (в пулю). Альтернатива `mountain` (списание такого же количества очков с горы).

Премия начисляется **каждому** игроку с нулём взяток (их может быть до двух).

### 8.6 Выход из распасов

**[КОНФИГ: `raspasyExit`]** — по умолчанию `simple`: после распасов торговля в следующей раздаче начинается снова с `6♠` без ограничений. Альтернативы: `hard` (6,7,7,7…), `strict` (6,7,8,8…) — минимальная заявка растёт с числом сыгранных подряд распасов.

**[КОНФИГ: `raspasyExitByRemise`]** — по умолчанию `allowed` (заявку можно сделать и заведомо проигрышную, «выход подсадом»).

**[КОНФИГ: `raspasyMaxInARow`]** — по умолчанию `unlimited`: ограничения «не более трёх распасов подряд» **нет**; счётчик перестаёт увеличивать цену на ×3 (см. §8.4). Альтернатива `3` (после трёх распасов подряд следующая раздача обязана быть сыгранной).

### 8.7 «Затмение» / раскрытые карты на распасах

**Не применяется.** Распасы всегда играются **втёмную**, карты не раскрываются, никакой вариант «в открытую» в v1 не поддерживается. «Шкаф» (серия вынужденных взяток) — не отдельное правило, а следствие обычного розыгрыша, отдельной записи не порождает.

## 9. Расчёт: пуля, гора, висты

### 9.1 Три области записи (пулька)

| Область | Что записывается | Курс в вистах |
|---|---|---|
| **Пуля** | очки за сыгранные игры на взятки и мизер; премия за 0 взяток на распасах | 1 очко = **+10 вистов** |
| **Гора** | штрафы за ремиз игрока, ремиз на висте, взятки на распасах | 1 очко = **−10 вистов** |
| **Висты** | висты, записанные игроками друг на друга | 1 вист = **1 вист** |

Записи только неотрицательными приращениями: очки из горы «сыгранной игрой» **не списываются** — в сочинке сыгранная игра всегда пишется в пулю. **[КОНФИГ: `playedGameBurnsMountain`]** — по умолчанию `off`; альтернатива `on` — конвенция «Ростов»/«Классика».

### 9.2 Стоимость игры

**Стоимость игры** (`gamePrice`) — единая величина, от которой считаются пуля, гора и висты в данной раздаче:

| Контракт | 6 | 7 | 8 | 9 | 10 | Мизер |
|---|---|---|---|---|---|---|
| Стоимость | **2** | **4** | **6** | **8** | **10** | **10** |

Стоимость **не зависит от масти козыря** (`6♠` и `6БК` стоят одинаково — 2). Масть влияет только на торговлю.

### 9.3 Сыгранный контракт (взятки ≥ заказа)

* Игрок: `пуля += gamePrice`.
* Каждый **вистовавший**: пишет на игрока висты `gamePrice × (взятки, засчитываемые ему, §9.4)`.
* Пасовавший: **ничего не пишет** (консоляции нет — контракт выполнен).
* Перебор (взяток больше заказа) **не даёт игроку дополнительных очков**, но уменьшает взятки обороны и потому может привести к ремизу на висте.

### 9.4 Висты за взятки обороны (тип виста)

**[КОНФИГ: `whistType`]** — по умолчанию **`zhlob`** («жлобский», характерен для сочинки):

* **Жлобский вист:** активный **вистующий** пишет висты за **все** взятки обороны — свои и взятки пасовавшего. **Пасовавший** не пишет ничего, кроме консоляции при ремизе игрока (§9.5).
* Если вистуют **оба** — каждый пишет висты за **свои** взятки.
* Альтернатива `gentleman` («джентльменский»): при ремизе игрока висты за взятки обороны делятся между вистовавшим и пасовавшим **поровну**; при нечётном числе вистов остаток — вистовавшему.

### 9.5 Ремиз игрока (взятки < заказа) и консоляция

Пусть `недобор = заказ − взятки игрока` (для мизера `недобор = взятки игрока`).

* Игрок: `гора += gamePrice × недобор`. **В пулю не пишется ничего.**
* Каждый **соперник** (и вистовавший, и пасовавший) дополнительно пишет на игрока **консоляцию**: `gamePrice × недобор` вистов **каждый**.
* Висты за фактические взятки обороны пишутся сверх консоляции по правилам §9.4.
* На **мизере** висты и консоляция **не пишутся** (`miserVists = none`), пишется только гора мизериста.

Нормативный пример (шестерная, `gamePrice = 2`, игрок без одной, вистовали оба, взятки обороны 3 и 2):

| | Взятки | За взятки | Консоляция | Итого вистов на игрока |
|---|---|---|---|---|
| Защитник A | 3 | 3×2 = 6 | 1×2 = 2 | **8** |
| Защитник Б | 2 | 2×2 = 4 | 1×2 = 2 | **6** |

Игрок пишет `1×2 = 2` в гору.

### 9.6 Ремиз на висте (недобор обязательных взяток)

**Вист ответственный** (нормативно для сочинки): за каждую недобранную обязательную взятку вистующий пишет **полную стоимость игры** в гору.

```
гора(вистующего) += gamePrice × max(0, обязательство − его зачётные взятки)
```

**[КОНФИГ: `whistResponsibility`]** — по умолчанию `full`; альтернатива `half` (полуответственный вист, половина стоимости игры за взятку).

Ремиз на висте **не отменяет** права вистующего писать висты за фактически взятые взятки.

### 9.7 Взятки на распасах

Только гора, по §8.3–8.4. Висты на распасах **не пишутся** (это отличает сочинку от «Ростова»). Премия за 0 взяток — в пулю (§8.5).

### 9.8 Закрытие пули и «американская помощь»

Партия играется до заранее оговорённой величины пули у **каждого** игрока (`poolTarget`, по умолчанию **10** очков; параметр партии).

**[КОНФИГ: `americanHelp`]** — по умолчанию `on`. Игрок, чья пуля достигла `poolTarget`, при следующей сыгранной игре **«помогает»**: очки за сыгранную игру он пишет **в пулю тому сопернику, у кого пуля наибольшая** (при равенстве — следующему по часовой стрелке от себя), а в качестве компенсации пишет **на него висты в десятикратном размере** (`gamePrice × 10`). Помощь не применяется при ремизе на висте у игрока с наибольшей пулей.

Партия заканчивается, когда пуля закрыта у всех троих.

### 9.9 Итоговая роспись пули

Обозначения для игрока `i`:

* `П_i` — очки в пуле, `Г_i` — очки в горе, `D_i = П_i − Г_i`;
* `V_i` — сальдо вистов: `(висты, записанные игроком i на других) − (висты, записанные другими на i)`.

**Нормативная формула итога (в вистах):**

```
Итог_i = 5 * Σ_{j≠i} (D_i − D_j) + V_i
```

Эквивалентная форма для трёх игроков:

```
Итог_i = 15*D_i − 5*(D_0 + D_1 + D_2) + V_i
```

Смысл: одно очко пули стоит +10 вистов, которые оплачивают **два** соперника по 5; одно очко горы стоит −10 вистов, распределяемых так же.

**Инварианты (обязательны к проверке тестами):**

* `Σ Итог_i = 0` — расчёт всегда с нулевой суммой.
* **«Амнистия горы»** (вычитание одинаковой величины из горы всех игроков) **не меняет итогов** — следовательно, это допустимая оптимизация отображения.
* Взаимные висты двух игроков сокращаются: сальдо `V_i` инвариантно к взаимозачёту.

**Разбор горы** («списание») в сочинке отдельной процедурой **не производится**: гора участвует в итоге как отрицательные очки по формуле выше. Конвертация вистов в деньги — умножение на цену виста (параметр партии, вне логики расчёта). Минимальные взаиморасчёты «кто кому должен» строятся поверх `Итог_i` (реализовано отдельно, см. `settleDebts`).

### А.3 Нормативный публичный API (контракт между модулями)

Модуль ядра (`core`) и модуль расчёта (`scoring`) связаны **только** структурой результата раздачи:

```ts
type DealOutcome =
  | { kind: 'contract'; contract: ContractId; declarer: PlayerId;
      tricks: Record<PlayerId, number>;                 // сумма = 10
      whisted: Record<PlayerId, boolean>;               // для двух соперников
      mode: 'dark' | 'light' }
  | { kind: 'miser'; declarer: PlayerId; declarerTricks: number }
  | { kind: 'raspasy'; tricks: Record<PlayerId, number>; consecutiveIndex: number };
```

`scoreDeal(outcome, options) -> ScoreDelta[]`, где `ScoreDelta = { player, pool, mountain, vistsOn: Record<PlayerId, number> }`.
`applyScore(scoreboard, deltas) -> scoreboard`; `finalize(scoreboard) -> Record<PlayerId, number>` (итог по §9.9, сумма = 0).

**Нормализация `ScoreDelta` (нормативно, чтобы сравнение в тестах было однозначным):**

1. `scoreDeal` возвращает **ровно по одной записи на каждого из трёх игроков**, в порядке `PlayerId` по возрастанию — даже если все поля нулевые.
2. `pool` и `mountain` — всегда числа (`0`, если записи нет); отрицательных значений не бывает: списание с горы в дефолтной конвенции не применяется (§9.1).
3. `vistsOn` содержит **только ненулевые** записи. Ключ с нулевым значением — **запрещён**: «вистов нет» кодируется отсутствием ключа, а не `{ "A": 0 }`. Это отличает TS-38 (десятерная проверяется, вистов нет вообще) от гипотетической записи нулевого виста.
4. `vistsOn` не может содержать ключ самого игрока (`vistsOn[self]` запрещён).
5. Складывать дельты в табло обязан только `applyScore`; сам `scoreDeal` — чистая функция без состояния партии. Единственное исключение — «американская помощь» (§9.8), которой нужна текущая пуля: она передаётся в `options.currentPool`.

## Приложение В. Краткий словарь

* **Пуля (пулька)** — область записи очков за сыгранные игры; также синоним партии.
* **Гора** — область записи штрафных очков.
* **Вист** — (а) минимальная единица расчёта; (б) заявка играть против игрока; (в) взятка вистующего.
* **Ремиз (подсад)** — невыполнение обязательства (игроком или вистующим).
* **Консоляция** — премиальные висты соперникам при ремизе игрока.
* **Распасы** — раздача после трёх пасов; цель — взять минимум взяток.
* **Мизер** — обязательство не взять ни одной взятки.
* **Прикуп** — 2 карты, откладываемые при сдаче; достаются выигравшему торговлю.
* **Снос** — 2 карты, сбрасываемые игроком после взятия прикупа.
* **Амнистия** — на распасах: вычитание минимального числа взяток у всех; при росписи: вычитание минимальной горы (итог не меняется, TS-42).
* **Первая рука** — игрок слева от сдающего; начинает торговлю.
* **Тотус** — десятерная игра.
* **Фоска** — младшая карта масти (7–10); термин описательный, на правила не влияет.
